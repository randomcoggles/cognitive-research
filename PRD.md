## 1. Executive Summary

The Atlas of Cognition is a comprehensive digital platform designed to map, explain, teach,
assess, and operationalize human cognition.

Unlike psychology textbooks, learning platforms, or AI knowledge assistants, the Atlas seeks to
answer two questions:

> **How does the human mind work as a system?**
>
> **How can humans use tools, AI, workflows, and practices to extend and improve cognition?**

The Atlas combines the following disciplines into a unified framework:

- Cognitive Science
- Educational Psychology
- Learning Sciences
- Knowledge Management
- Human Factors Engineering
- Systems Thinking
- Artificial Intelligence
- Productivity Systems

The final product functions as all of the following at once:

- Encyclopedia
- Knowledge Graph
- Learning Platform
- Assessment System
- Cognitive Development Environment
- Human + AI Cognitive Operating System

## 11. Assessment Framework

The Atlas includes a learning engine. Every concept supports six levels of assessment, based on
Bloom's Taxonomy.

| Level | Question the assessment asks |
|---|---|
| **Recall** | Can the learner remember? |
| **Understanding** | Can the learner explain? |
| **Application** | Can the learner use it? |
| **Analysis** | Can the learner diagnose? |
| **Evaluation** | Can the learner judge? |
| **Creation** | Can the learner design with it? |

### Why this matters

Most learning systems stop at the first level:

> *"Can you remember the definition?"*

That is the lowest level of learning. The Atlas should assess all six.

| Level | Example question |
|---|---|
| Remember | What is Working Memory? |
| Understand | Explain why Working Memory becomes overloaded. |
| Apply | Identify Working Memory limitations in this scenario. |
| Analyze | Compare Working Memory and Long-Term Memory. |
| Evaluate | Which tool best supports Working Memory in this case? |
| Create | Design a workflow that reduces Working Memory load. |

### Assessment profile

Each concept should define a weighting across the six levels:

```json
{
  "concept": "Working Memory",
  "assessmentProfile": {
    "remember": 20,
    "understand": 25,
    "apply": 30,
    "analyze": 15,
    "evaluate": 5,
    "create": 5
  }
}
```

Meaning:

| Level | Weight |
|---|---|
| Recall | 20% |
| Understanding | 25% |
| Application | 30% |
| Analysis | 15% |
| Evaluation | 5% |
| Design | 5% |

This produces much deeper learning than recall-only assessment.

### Proposed assessment formula

An alternative weighting that favours real-world competence:

| Type | Weight |
|---|---|
| Recall | 10% |
| Understanding | 20% |
| Application | 30% |
| Scenario Analysis | 25% |
| Reflection | 5% |
| Tool Selection | 10% |

## 12. Assessment Types

The Atlas should support many kinds of questions.

### Type 1 — Multiple Choice

**Good for:** definitions, recognition, terminology.

> Which memory system temporarily holds information while reasoning?
>
> - Episodic Memory
> - Semantic Memory
> - **Working Memory ✓**
> - Procedural Memory

### Type 2 — Multiple Select

**Good for:** relationships.

> Which external tools extend Working Memory? *Select all:*
>
> - **OneNote ✓**
> - **Whiteboard ✓**
> - SharePoint
> - **Sticky Notes ✓**

### Type 3 — Matching

Excellent for the Atlas.

| Concept | Match |
|---|---|
| Working Memory | Sticky Notes |
| Schema | Playbook |
| Executive Control | Jira |
| Metacognition | Reflection Journal |

### Type 4 — Ordering

> Arrange into the correct dependency order:
>
> Attention · Working Memory · Executive Control · Decision Making

### Type 5 — Relationship Mapping

Very powerful.

> **Working Memory** — *?* — **Executive Control**
>
> Find the relationship.

### Type 6 — Scenario Questions

The most important type.

> John is on an incident bridge. He is handling:
>
> - 50 open logs
> - Teams messages
> - Email alerts
> - Dashboard alarms
>
> He misses a key indicator. Which cognitive limitation is most likely involved?
>
> - Metacognition
> - Cognitive Flexibility
> - **Working Memory Overload ✓**
> - Semantic Memory

This measures understanding rather than memorization.

### Type 7 — Workplace Diagnosis

> A team constantly switches between unfinished tasks and never reaches completion.
>
> What executive function appears weakest?

Much closer to real life.

### Type 8 — Reflection

No right answer.

> Describe a time when poor metacognition caused a mistake.

These responses could be stored.

### Type 9 — Cognitive Tool Selection

Unique to the Atlas.

> You must remember 15 dependencies during Sprint Planning. Choose the best external cognitive tool:
>
> - Jira
> - Whiteboard
> - OneNote
> - Architecture Diagram
>
> Explain why.

### Type 10 — AI Partner Questions

> A Copilot assistant summarizes requirements. Which human cognitive function is being primarily extended?
>
> - **Working Memory ✓**
> - Procedural Memory
> - Inhibition
> - Empathy

## 2. Architecture decisions already made (do not re-litigate)

| Decision | Choice | Consequence |
|---|---|---|
| Module system | **Classic scripts + `window.Atlas` namespace** | No build step; `file://` works. Do **not** convert to ES modules. |
| Content model | **Data modules per domain** | Edit `data/`, not HTML |
| Lens placement | **Per-domain subpages** | `/<id>/reader.html`, `/<id>/creator.html` |
| Concept pages | **One dynamic shell** | `concept.html?c=<slug>` — not one file per concept |
| Quiz | **Item bank → sampled form + practice** | Not one fixed quiz |
| Lens quizzes | **Separate practice sets** | Lens items excluded from the scored assessment |
| URL scheme | **Domain at root** | `/attention/index.html`, not `/domains/attention/` |
| Rollout | **Pilot then replicate** | Attention is the reference implementation |

### Why classic scripts, not ES modules

`import` requires HTTP. The site must also work when opened from the filesystem.
Classic scripts with `defer` preserve execution order and work in both contexts.

### Why explicit `index.html` in links

Directory URLs (`/attention/`) do not resolve on `file://`. Every internal link uses
`attention/index.html`. This works locally and on GitHub Pages.

## 3. The namespace and URL helpers

`assets/app/namespace.js` must load **first**. It creates:

```js
window.Atlas = window.Atlas || {};
Atlas.data = Atlas.data || {};
Atlas.root = /* absolute URL of the atlas root, derived from this script's own src */;
Atlas.url = path => Atlas.root + path;   // use for EVERY internal link
```

**Rule: never write a relative `href` in JavaScript.** Always `Atlas.url("...")`.
Pages live at different depths, so relative paths break. This was a real bug: from
`/attention/`, `concept.html` resolved to `/attention/concept.html`.

Two helpers in `core.js` wrap this for domains:

```js
domainHref(domain)              // → <root>attention/index.html
domainSectionHref(domain, "x")  // → <root>attention/index.html#x
```

## 6. Data schemas

### `data/index.js` — lightweight, loaded everywhere

```js
Atlas.data.domainIndex = [
  { id, number, name, shortName, purpose, color, status, page, concepts, relations }
];
```

`concepts` is `[[name, description], ...]`. `relations` is `[conceptName, ...]`.

### `data/domains/<id>.js` — heavy, loaded per domain

```js
Atlas.data.domainContent = Atlas.data.domainContent || {};
Atlas.data.domainContent["attention"] = {
  objectives: [string],
  examples:   [[context, text]],
  mappings:   [[humanFunction, tool, aiExtension, guardrail]],
  failures:   [[name, description]],
  quiz:       [ /* legacy 7-question array — see §9 */ ]
};
```

`data.js` merges index + content into `atlasDomains`. A domain with `status: "ready"`
must have all five keys or `assertDomainData()` logs a problem.

### `data/domains/<id>/reader.js`

```js
Atlas.data.lenses["attention"].reader = {
  title, standfirst,
  principles: [{ title, body, do }],      // 5 items
  practices:  [string],                    // 6 items
  pitfalls:   [[name, text]],              // 4 items
  example:    { context, before, after }
};
```

### `data/domains/<id>/creator.js`

```js
Atlas.data.lenses["attention"].creator = {
  title, standfirst,
  principles: [{ title, body, do }],      // 6 items
  protocolMapping: {                       // optional but strongly preferred
    note,
    steps: [[phase, protocolStep, whyItMatters]]
  },
  checklist: [string],                     // 6 items
  pitfalls:  [[name, text]],               // 4 items
  example:   { context, before, after }
};
```

### `data/domains/<id>/quiz.js`

```js
Atlas.data.itemBanks["attention"] = {
  form: {
    size: 10,
    blueprint: { remember: 1, understand: 2, apply: 3, analyze: 2, evaluate: 1, create: 1 },
    lens: "concept"        // only concept items enter the scored form
  },
  items: [
    { id, level, lens, type, prompt, options, answer, explanation }        // single choice
    { id, level, lens, type, prompt, options, answers, explanation }       // multiple select
  ]
};
```

- `level` ∈ `remember | understand | apply | analyze | evaluate | create`
- `lens` ∈ `concept | reader | creator`
- `type` ∈ `"Single choice" | "Multiple select"`
- `id` convention: `att-<lvl3>-<nn>` (e.g. `att-app-03`)

## 7. The two lenses — the core idea

Each domain gets **two dual perspectives on the same mechanism**:

- **Reader lens** — how a *reader* compensates for this system's limits.
- **Creator lens** — how an *author/instructional designer* designs *for* those limits.

Same mechanism, opposite direction of control. This symmetry is the pedagogical point;
do not collapse the two into one page.

### Editorial template (follow it exactly)

**Reader lens** — 5 principles, each with:
1. A claim as the title ("You cannot read two things at once")
2. The mechanism, in one or two sentences
3. A `do` field: one concrete action

Then: 6 practices, 4 pitfalls, one before/after worked contrast.

**Creator lens** — 6 principles (same shape), then:
- A `protocolMapping` table tying principles to the existing reader-support protocol
- A 6-item pre-publish checklist
- 4 pitfalls
- One before/after worked contrast

**Voice:** declarative, mechanism-first, no hedging, no motivational filler. Every
principle must name a real cognitive mechanism (vigilance decrement, split-attention
effect, seductive details, switching cost, etc.), not a generic study tip.

### Source material for the lenses

These five files (one level above `atlas/`) are the origin of the lens idea. Mine them;
do not link to them from the site.

| File | Use |
|---|---|
| `reader-support-protocol.html` | The 7-part design protocol + 22 protocol steps. Source for every `protocolMapping`. |
| `cognitive-reading-process.html` | Reading as a pipeline through cognitive systems. Reader-lens framing. |
| `cognitive-kitchen-scene.html` | Same idea as a scene/metaphor. Alternate framing. |
| `cognitive-instruments.html` | Working memory, chunking, schema, metacognition visual guide. Concept-layer reference. |
| `cognitive-kitchen-scene copy.html` | Byte-identical duplicate. Ignore. |

The protocol categories are already encoded in `concept.js` as `protocolCategories`
(ATT, WM, KN, MOD, EX, META, MOT) and `protocolItems` (22 steps with per-category
weights). Reuse them; do not re-derive.

## 8. Procedure: adding a domain (the main remaining task)

Repeat for each of: `memory`, `executive`, `knowledge`, `reasoning`, `learning`,
`creativity`, `social`, `self-regulation`, `future`, `decision`, `metacognition`.

**Step 1 — create the data subfolder**

```
data/domains/<id>/reader.js
data/domains/<id>/creator.js
data/domains/<id>/quiz.js
```

Copy the Attention files as templates. Change the namespace key from `"attention"` to
the new id in all three.

**Step 2 — write the lenses**

Use §7's template. The domain's own `failures` and `mappings` (already in
`data/domains/<id>.js`) tell you which mechanisms matter — the lenses should address
those same mechanisms from the reader's and creator's side.

**Step 3 — write the item bank**

Target **24 concept items** (4 per Bloom level) + **4 reader** + **4 creator** = 32.
The blueprint needs at least one item per level; 4 per level gives the sampler room.

**Step 4 — create the three page shells**

Copy `attention/reader.html`, `attention/creator.html`, `attention/quiz.html`. In each:

- change `data-domain="attention"` to the new id
- change the three `data/domains/attention/*.js` script tags to the new id
- change the `<title>`

Nothing else in the shell changes — the renderers are generic.

**Step 5 — verify**

Open all four pages for the domain. Check:

- no console errors
- reader lens shows 5 principles, creator lens 6
- assessment shows exactly 10 questions with all six Bloom levels present
- practice shows the full bank; `?lens=reader` and `?lens=creator` filter correctly
- scoring persists to `localStorage` under `atlas-cognition:bank:<id>`

**Step 6 — add lens links to the domain page**

Already automatic: `renderDomain()` in `core.js` emits the three lens buttons for every
domain. No change needed.

## 9. Known issues and deliberate omissions

**The legacy 7-question quiz still runs on domain pages.** `quiz.js` and the `quiz`
array in `data/domains/<id>.js` predate the item bank. Both exist side by side. The
intent is to retire the legacy quiz in favour of the bank, but that is a content
decision, not a refactor — **ask the owner before removing it.**

**Lens knowledge is not scored.** Because `form.lens === "concept"`, the 10-item
assessment contains no reader/creator items. Lens items are practice-only. If the owner
wants them counted, change `form.lens` to a mix and extend `sampleForm()` in `bank.js`.

**`concept.js` is 759 lines** and holds `conceptDetails` — 85 per-concept records. That
is content, not logic, and belongs in `data/`. It was left in place to avoid mixing a
refactor with a content migration. Splitting it is a reasonable next cleanup.

**Two note implementations were merged into one** (`notes.js`). Do not reintroduce a
second one. A previous duplicate caused a bug where the concept page silently lacked
the outside-click handler.

**`[hidden]` needs `!important`.** `styles.css` has `[hidden] { display: none !important; }`
because `.plain-button { display: inline-flex }` and `.note-form label { display: grid }`
otherwise override the UA rule. Do not remove it.

**Encoding.** Windows PowerShell 5.1 defaults to ANSI. When reading or writing these
files from PowerShell, always use:

```powershell
$utf8 = New-Object System.Text.UTF8Encoding $false
[System.IO.File]::ReadAllText($path, $utf8)
[System.IO.File]::WriteAllText($path, $text, $utf8)
```

Using `Get-Content -Raw` / `Set-Content` corrupts `·`, `↔`, `—` into mojibake. This
already happened once and had to be repaired in 7 files.

## 12. Deployment

Static site, no build step. Serve the `atlas/` folder as the web root.

- **GitHub Pages:** push the contents of `atlas/` to the publishing branch. Directory
  URLs work there, but the code uses explicit `index.html` so local and hosted behaviour
  match.
- **Local preview:** `python -m http.server` from inside `atlas/`, or open
  `index.html` directly (works because of classic scripts).
- **No service worker yet.** A PWA requires HTTPS; `file://` cannot register one.
